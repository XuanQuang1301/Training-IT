https://api.sydexa.vn:80/users/search?name=Minh&role=admin#results
Đầy đủ 9 thành phần chính của URL
Thành phần Giá trị mẫu Mô tả chi tiết
Scheme / Protocol https:// Nằm trước ://, giao thức kết nối. HTTPS có mã hóa bảo mật.
Subdomain api Đứng trước domain chính, dùng phân chia vùng app (API, blog, admin).
Domain sydexa Tên định danh chính của website/tổ chức (giống địa chỉ tòa nhà).
TLD .vn Tên miền cấp cao nhất, cho biết loại hình/quốc gia (.com, .org, .edu).

Path /users/search Sau host, trước dấu ?. Đường dẫn tới tài nguyên cụ thể.
Query Separator ? Cầu nối báo path đã kết thúc, bắt đầu tham số truy vấn.
Query Params name=Minh&role=admin Dữ liệu lọc key=value gửi server, nối bằng dấu &.
Fragment #results Neo trang do Browser xử lý để cuộn màn hình. KHÔNG gửi server.

Root-relative /users/search Nội bộ cùng Origin
Path-relative ./detail hoặc ../ Tương đối từ thư mục hiện tại

1.2 Origin, Cơ Chế CORS & Luồng DNS

Origin & Cơ Chế Bảo Mật CORS
  • Origin = Protocol + Host + Port.
  • Nếu 1 trong 3 yếu tố khác nhau → Cross-Origin Request.
  • CORS: Cơ chế bảo mật do Browser kiểm tra response header (Access-Control-Allow-Origin) từ Server.
  • Same-origin request cho phép mặc định; Cross-origin request cần server cấp phép.
3 Bước Tra Cứu DNS (DNS Resolution)
  • Bước 1: Trình duyệt kiểm tra Browser DNS Cache.
  • Bước 2: Trình duyệt kiểm tra OS DNS Cache.
  • Bước 3: Hỏi Recursive Resolver (ISP / 1.1.1.1 / 8.8.8.8) đi lần lượt qua các server:
    Root Name Server → TLD Server (.com/.vn) → Authoritative Server (Trả về IP thực sự)
1. Root Server (Gốc): Có 13 cụm toàn cầu (a đến m.root-servers.net). Không chứa IP cụ thể, chỉ điều hướng resolver sang TLD Server quản lý phần đuôi (ví dụ .com).
2. TLD Server (Cấp cao nhất): Quản lý đuôi miền (.com, .vn...). Nắm danh sách và chỉ đường tiếp đến Authoritative Server có thẩm quyền của tên miền con.
3. Authoritative Server (Thẩm quyền): Nắm bản ghi DNS gốc (Cloudflare, AWS Route 53...). Tra bảng và trả về IP thực sự (bản ghi Type A / AAAA) cho Resolver.

1.4 Biến, Scope & Phương Thức Mảng JS

Biến & Immutability trong React
  • var: Function scope, hoisting (Tránh sử dụng trong React).
  • let: Block scope `{}` cho phép gán lại giá trị (reassign).
  • const: Block scope `{}` không cho gán lại reference.
  • Chú ý React: Trong State, không mutate trực tiếp object/array mà luôn tạo Reference mới (Immutability).
Bộ Ba Phương Thức Mảng Cốt Lõi
  • map(): Biến đổi từng phần tử thành mảng mới cùng độ dài (Dùng render list JSX).
  • filter(): Lọc ra các phần tử thỏa mãn điều kiện.
  • reduce(): Gom mảng về 1 giá trị duy nhất (số, object, mảng mới).

1.5 Event Loop & Cú Pháp JS Modern

Event Loop (Đơn Luồng JS)
  • Call Stack: Thực thi các đoạn mã đồng bộ.
  • Microtask Queue: Ưu tiên cao (Promise, `async/await`).
  • Macrotask Queue: Ưu tiên thấp (`setTimeout`, `setInterval`).
  • Thứ tự: Call Stack trống → Chạy hết sạch Microtasks → Chạy 1 Macrotask.
Cú Pháp Modern JS Cần Thiết
  • ?. (Optional Chaining): Tránh fatal crash khi truy cập thuộc tính `null`/`undefined`.
  • ?? (Nullish Coalescing): Giữ lại `0`, `""`, `false` (chỉ lấy vế sau khi vế trước `null`/`undefined`).
  • finally trong `try-catch`: Luôn luôn chạy để tắt trạng thái loading.

2.2 Bộ Tứ Đặc Biệt & Interface/Type

Bộ Tứ: void, never, any, unknown
  • void: Hàm không trả về giá trị (return undefined).
  • never: Giá trị KHÔNG BAO GIỜ xảy ra (throw error / loop vô tận).
  • any: Tắt kiểm tra kiểu (Nguy hiểm, nên tránh).
  • unknown: An toàn hơn `any`, bắt buộc Type Narrowing trước khi dùng.
Interface vs Type cho Props
// Interface dùng cho React Props
interface ButtonProps {
  label: string;
  onClick: () => void;
  disabled?: boolean;
}

// Type dùng cho Union Types
type Status = "idle" | "loading" | "success";

Tiêu chí SSR (Server Side Rendering) CSR (Client Side Rendering)
Nơi render Server Trình duyệt (Browser)
HTML ban đầu Hoàn chỉnh, đầy đủ nội dung Vỏ trống <div id="root"></div>

3.1 SSR vs CSR: Ưu Điểm, Nhược Điểm & Kết Luận

SSR (Server Side Rendering)
Render tại Server
Ưu Điểm Nổi Bật
  • Tốc độ hiển thị lần đầu nhanh: HTML có sẵn giúp FCP tối ưu.
  • SEO tuyệt vời: HTML đầy đủ cho crawler thu thập dữ liệu.
  • Hiển thị tốt trên thiết bị cấu hình yếu: Server gánh tải xử lý.
Nhược Điểm Cần Chú Ý
  • Server chịu tải nặng: 100.000 người = 100.000 lần render.
  • Hiện tượng Uncanny Valley: Thấy nút bấm nhưng chưa tương tác được (chờ Hydration).
  • Mỗi lần chuyển trang là round-trip đến server: Tăng độ trễ mạng.
CSR (Client Side Rendering)
Render tại Trình duyệt
Ưu Điểm Nổi Bật
  • UX mượt sau lần load đầu: Chuyển trang tức thì không reload.
  • Giảm tải server: Server chỉ trả static assets và xử lý API JSON.
  • Offline Support tốt: Dễ dàng cache App Shell & data người dùng.
Nhược Điểm Cần Chú Ý
  • Lần load đầu chậm: JS bundle lớn (500KB+), cần thời gian tải & parse.
  • SEO kém: Crawler khó đọc nội dung render động từ JS.
  • Phụ thuộc JavaScript hoàn toàn: Tắt JS hoặc lỗi script là trắng trang.
KẾT LUẬN: KHÔNG CÓ WINNER TUYỆT ĐỐI, CHỈ CÓ ĐÚNG CONTEXT
• SSR thắng ở: Tốc độ hiển thị ban đầu (FCP) và tối ưu SEO cho công cụ tìm kiếm.
• CSR thắng ở: Trải nghiệm tương tác mượt mà (UX) và giảm tải chi phí hạ tầng máy chủ.
• Câu trả lời đúng luôn là: Phụ thuộc vào bài toán của bạn! (Xu hướng hiện đại: Kết hợp kiến trúc Hybrid Rendering như Next.js / Remix – SSR cho Landing/E-commerce, CSR cho App Dashboard/Interactive).

3.2 SPA vs MPA (Kiến Trúc Ứng Dụng Web)

Lưu ý quan trọng: SSR / CSR nói về CÁCH RENDER (Server hay Trình duyệt dựng HTML). Còn SPA / MPA nói về KIẾN TRÚC ỨNG DỤNG
Tiêu chí SPA (Single Page Application) MPA (Multi Page Application)
Số trang HTML 1 HTML duy nhất + Client JS Router N trang HTML riêng biệt từ Server
Khi chuyển trang (vd: click "About") Content fade out → fade in nội dung mới. URL đổi nhưng trang KHÔNG reload, giữ nguyên Shell Flash trắng toàn màn hình: Trang MỚI hoàn toàn load lại từ đầu, render lại tất cả elements
Tốc độ chuyển trang ~50ms Gần như tức thì ~800ms Phải chờ server response + full reload
Cơ chế hoạt động 1 HTML + JS Router – Chỉ thay đổi phần cần thay đổi N HTMLs + Server render – Mỗi trang là một request mới
SPA (Single Page Application)
1 Trang HTML

Chỉ tải MỘT trang HTML duy nhất. Mọi điều hướng và thay đổi nội dung do JavaScript xử lý. Không reload, không flash trắng, UX mượt mà như Native App.

Ứng dụng tiêu biểu: Gmail, Figma, Notion, Facebook Web, Trello.
MPA (Multi Page Application)
N Trang HTML

Kiến trúc web truyền thống. Mỗi URL là một trang HTML riêng biệt từ máy chủ. Click link đồng nghĩa với full page reload (gửi request mới, tải lại toàn bộ trang).

Ứng dụng tiêu biểu: Wikipedia, Trang tin tức (BBC, VnExpress), E-commerce truyền thống.

3.3 Tooling Modern & Cấu Trúc Dự Án

Công Cụ Modern (Vite & pnpm)
Build Tool & Package

3.4 Tiến Hóa: Class vs Function Component

Class Component
Legacy (Cũ)
  • Rắc rối với con trỏ this: Dễ crash runtime nếu quên bind hàm thủ công trong constructor.
  • Lifecycle Hell: Cùng 1 logic (subscribe / cleanup) bị xé nhỏ ra 3 hàm lifecycle (componentDidMount, componentDidUpdate, componentWillUnmount).
  • Khó tái sử dụng logic: Phải dựa vào Higher-Order Components (HOC) hoặc Render Props, làm lồng ghép cây component phức tạp.
  • Code rườm rà (Boilerplate): Tốn nhiều dòng code chỉ để khai báo class, constructor và state.
Function Component + Hooks
Modern Standard
  • Không còn con trỏ this: Đơn giản là JavaScript function thuần túy, nhận props và trả về JSX trực quan.
  • Gom gọn logic với useEffect: Toàn bộ logic khởi tạo, lắng nghe và dọn dẹp tài nguyên được gom gọn vào 1 hook duy nhất.
  • Dễ chia sẻ bằng Custom Hooks: Tách logic dùng chung thành hàm riêng biệt mà không làm thay đổi phân cấp UI.
  • Code ngắn hơn ~60%: Rõ ràng, dễ đọc, dễ viết Unit Test và tối ưu hiệu năng bundle size.
• Kết luận thực tế: 100% dự án React mới ngày nay sử dụng Function Component + Hooks. Học Class Component chỉ phục vụ việc đọc hiểu và bảo trì các hệ thống cũ (legacy code).

Kiến Trúc & Luật Bất Biến
8 Hooks Cốt Lõi

  • Quy tắc tối thượng: Chỉ gọi hook ở top-level của component; tuyệt đối không đặt trong if/else, vòng lặp hay hàm lồng.

Core Foundation

  • 3. useLayoutEffect: Đo đạc & sửa DOM đồng bộ trước Paint để chặn nháy hình (flicker).
  • 4. useReducer: Quản lý State phức tạp tập trung theo mô hình Action/Reducer.
Trọng tâm: Làm chủ bộ tứ này là nắm chắc 90% logic vận hành của React.

4.2 useState - Quản Lý Trạng Thái (State) Nội Bộ

Khái niệm: useState dùng để lưu trữ và cập nhật dữ liệu động (State) bên trong Function Component.
Khi State thay đổi, React tự động kích hoạt Re-render để cập nhật UI.
Cú pháp: const [state, setState] = useState(initialValue);
Stale Closure & Functional Update
Cập Nhật An Toàn
  • Bẫy Stale Closure: Gọi setCount(count + 1) 3 lần liên tiếp vẫn chỉ tăng 1, vì biến count bị "đóng băng" ở snapshot render hiện tại.
  • Functional Update: Luôn dùng setCount(prev => prev + 1) khi state mới tính từ state cũ để luôn lấy giá trị mới nhất.
  • Batching (React 18): React tự động gom nhiều lần setState trong cùng tick thành duy nhất 1 lần re-render để tối ưu hiệu năng.
Quy tắc: State mới phụ thuộc state cũ → Luôn dùng hàm callback prev => ....
Lazy Initialization (Khởi Tạo Lười)
Tối Ưu Hiệu Năng
  • Vấn đề: useState(expensiveCalc()) khiến hàm tính toán bị gọi lại ở MỌI lần re-render (lãng phí CPU).
  • Giải pháp: useState(() => expensiveCalc()) truyền callback để React chỉ gọi 1 lần duy nhất khi Mount.
  • Ứng dụng thực tế: Đọc dữ liệu từ localStorage, parse JSON dung lượng lớn, hoặc tạo cấu trúc mảng ban đầu.
Quy tắc: Giá trị khởi tạo tốn tài nguyên → Luôn bọc trong hàm () => compute().
PHẦN 4: REACT HOOKS

4.3 useEffect - Quản Lý Tác Vụ Phụ (Side Effect)

Khái niệm: useEffect dùng để đồng bộ component với các hệ thống bên ngoài (Side Effect) như gọi API, lắng nghe event, Timer, thao tác DOM.
Cơ chế: Chạy bất đồng bộ SAU KHI trình duyệt đã vẽ UI (After Paint) để không chặn giao diện.
Dependency Array (Kiểm Soát Vòng Đời)
Khi Nào Chạy?
  • Không truyền mảng useEffect(fn): Chạy lại sau mọi lần render của component.
  • Mảng rỗng useEffect(fn, []): Chỉ chạy 1 lần duy nhất khi Mount (tương tự componentDidMount).
  • Có dependencies useEffect(fn, [deps]): Chỉ chạy lại khi có ít nhất 1 dependency thay đổi (so sánh Object.is).
Lưu ý: React 18 Strict Mode cố ý mount 2 lần ở môi trường Dev để phát hiện rò rỉ bộ nhớ.
Cleanup Function (Dọn Dẹp Bộ Nhớ)
Tránh Memory Leak
  • Cú pháp: Trả về một hàm dọn dẹp: return () => { /* hủy tác vụ */ };
  • Thời điểm thực thi: Chạy ngay trước effect kế tiếp và khi component Unmount khỏi DOM.
  • Nhiệm vụ bắt buộc: Hủy clearInterval, gỡ removeEventListener, ngắt WebSocket, abort fetch request.
Quy tắc: Mở kết nối / timer trong effect thì BẮT BUỘC phải dọn dẹp trong hàm return.
PHẦN 4: REACT HOOKS

4.4 useLayoutEffect - Xử Lý DOM Đồng Bộ Trước Khi Paint

Khái niệm: useLayoutEffect chạy ĐỒNG BỘ sau khi DOM cập nhật nhưng TRƯỚC KHI trình duyệt vẽ (Before Paint).
Chặn browser vẽ để đọc/sửa DOM ngay lập tức nhằm triệt tiêu hoàn toàn hiện tượng nháy hình (Flicker).
So Sánh: useEffect vs useLayoutEffect
Chặn Vẽ UI
Tiêu chí useEffect useLayoutEffect
Thời điểm SAU Paint (Async) TRƯỚC Paint (Sync)
Chặn UI Không chặn browser Chặn browser vẽ
Ứng dụng API, timer, event Đo DOM, scroll, layout
Quy tắc: 99% tác vụ dùng useEffect. Chỉ dùng useLayoutEffect khi người dùng thấy layout bị giật nảy.
3 Kịch Bản Sử Dụng Thực Tế
Thực Tiễn
  • 1. Đo đạc DOM: Đo chiều cao container cho Virtual Scroll hoặc đo kích thước Tooltip để căn vị trí không tràn viewport.
  • 2. Đồng bộ vị trí Scroll: Reset scrollTop = 0 ngay tức thì khi chuyển trang để tránh bị nảy khung hình.
  • 3. Khởi tạo Animation: Thiết lập vị trí/opacity ban đầu trước khi vẽ (tránh Flash of Unstyled Content).
  • Lưu ý SSR: Trên Next.js/SSR cần dùng useIsomorphicLayoutEffect để tránh cảnh báo lỗi server.
Cảnh báo: Không gọi API hay tính toán nặng trong useLayoutEffect vì sẽ làm đơ giao diện.
PHẦN 4: REACT HOOKS

4.5 useReducer - Quản Lý Trạng Thái Phức Tạp Tập Trung

Khái niệm: useReducer dùng để quản lý State phức tạp hoặc nhiều state phụ thuộc nhau thông qua một hàm Reducer tập trung duy nhất theo mô hình: (state, action) => newState.
Cú pháp: const [state, dispatch] = useReducer(reducer, initialArg);
Cơ Chế & 3 Nguyên Tắc Reducer
Hàm Thuần Túy
  • Cơ chế hoạt động: Component chỉ gửi hành động qua dispatch(action), toàn bộ logic biến đổi state do Reducer quyết định.
  • 1. Pure Function: Cùng input (state + action) luôn trả về cùng 1 output duy nhất, không ngẫu nhiên.
  • 2. Immutability Tuyệt Đối: Không mutate state cũ (không push/splice), luôn tạo object/array mới.
  • 3. Không Side Effect: Tuyệt đối không gọi API, timer hay can thiệp DOM bên trong reducer.
Stable Reference: Hàm dispatch không bao giờ đổi địa chỉ bộ nhớ qua các render.
Khi Nào Dùng useState vs useReducer?
Lựa Chọn Đúng
  • Chọn useState khi: State đơn giản, độc lập (1-3 biến: boolean toggle, input string, counter).
  • Chọn useReducer khi: Nhiều state phụ thuộc nhau (ví dụ: data, isLoading, error), form phức tạp, CRUD danh sách.
  • Dễ Unit Test: Tách 100% logic cập nhật ra khỏi component UI → Viết test cho reducer cực kỳ đơn giản.
Quy tắc: State độc lập → useState. State chùm, phụ thuộc lẫn nhau → useReducer.
