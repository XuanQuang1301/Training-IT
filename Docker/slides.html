Phần 2.1

Dockerfile — Khái Niệm & Cấu Trúc Lệnh

Mục đích: File văn bản thuần túy chứa chỉ thị tự động dựng môi trường mà không cần gõ từng lệnh trên terminal.

FROM

Chọn Base Image nền tảng (Node, Python, Ubuntu,...).

WORKDIR

Tạo và chuyển đến thư mục làm việc trong container.

COPY

Chép file từ máy thật (Host) vào bên trong container.

RUN

Chạy các lệnh cài thư viện (npm install, apt).

EXPOSE

Khai báo cổng (Port) mà ứng dụng sẽ lắng nghe.

CMD

Lệnh mặc định khởi chạy ứng dụng khi container bật.

Phần 2.1

Dockerfile — Ví Dụ Minh Họa

# Bước 1: Mượn môi trường có sẵn Node.js 18
FROM node:18-alpine

# Bước 2: Tạo thư mục /app trong container để chứa code
WORKDIR /app

# Bước 3: Copy file khai báo thư viện và tải về
COPY package*.json ./
RUN npm install

# Bước 4: Copy toàn bộ code từ máy thật vào thư mục /app
COPY . .

# Bước 5: Khai báo cổng 3000 và lệnh khởi chạy
EXPOSE 3000
CMD ["node", "server.js"]
Phần 2.2

Image — Bản Đóng Gói Chỉ Đọc

Mục đích: Là sản phẩm tạo ra sau khi Docker thực thi xong Dockerfile, chứa toàn bộ mã nguồn, thư viện, runtime & tools.

ĐẶC ĐIỂM 1

Read-only (Chỉ Đọc)

Không ai sửa đổi trực tiếp vào Image được. Nó giống như một file nén .zip đã đóng băng hoàn toàn dữ liệu ban đầu.

ĐẶC ĐIỂM 2

Chia Sẻ Dễ Dàng

Có thể đẩy lên Docker Hub để đồng nghiệp kéo về khởi chạy ngay lập tức mà không lo lỗi khác biệt hệ điều hành.

Phần 2.2

Image — Các Lệnh Quản Lý Cơ Bản

BUILD
Tạo Image từ Dockerfile

Lệnh: docker build -t my-web-app:v1 .

LIST
Xem danh sách Image trên máy

Lệnh: docker images

REMOVE
Xóa Image không dùng

Lệnh: docker rmi my-web-app:v1

Phần 2.3

Container — Thực Thể Đang Chạy

KHÁI NIỆM

Running Instance

Container là thực thể đang chạy được khởi tạo từ Image. Có CPU, RAM, ổ đĩa và mạng hoàn toàn cách ly.

KHẢ NĂNG MỞ RỘNG

1 Image -> N Containers

Từ 1 Image có thể bật ra 10 hay 1000 Container cùng lúc trên các cổng 3001, 3002, 3003 để chia tải.

CẢNH BÁO LƯU TRỮ

Dữ Liệu Tạm Thời (Ephemeral State)

Khi Container dừng và bị xóa (docker rm), những gì phát sinh trong quá trình chạy sẽ bị mất vĩnh viễn (trừ khi dùng Docker Volume).

Phần 2.3

Container — Các Lệnh Quản Lý Cơ Bản

Lệnh khởi chạy từ Image:

docker run -d -p 8080:3000 --name my-running-app my-web-app:v1
-d

Chạy ngầm trong nền (*Detach mode*).

-p 8080:3000

Chuyển tiếp cổng Host:Container.

--name

Đặt tên nhận diện cho container.

Phần 2.4

Khi Nào Cần Có Dockerfile?

TRƯỜNG HỢP CẦN DOCKERFILE
• Tự đóng gói mã nguồn app (Node.js, Spring Boot, React).
• Tùy biến sâu Image (cài ffmpeg, sửa nginx.conf).
• Tự động hóa build trong quy trình CI/CD.
TRƯỜNG HỢP KHÔNG CẦN
• Dùng dịch vụ có sẵn: MySQL, Postgres, Redis, Nginx.
Lý do: Đã có sẵn Official Image trên Docker Hub, chỉ cần kéo về chạy trực tiếp.
Phần 2.5

Docker Volume — Dữ Liệu Bền Vững

Giải pháp: Tách biệt hoàn toàn phần Dữ liệu ra khỏi Vòng đời của Container.

BƯỚC 1 & 2

Lưu Trữ Ở Máy Thật

Volume là thư mục nằm trên máy thật (Host Machine) do Docker quản lý. Data ghi trong container bay thẳng xuống máy thật.

BƯỚC 3 & 4

An Toàn Tuyệt Đối

Khi xóa Container, Volume vẫn còn nguyên. Tạo container mới chỉ cần gắn lại Volume cũ, dữ liệu lập tức quay trở lại.

Phần 3

Vấn Đề Khi Có Nhiều Container

VẤN ĐỀ 1

Lệnh Chạy Thủ Công Dài

Chạy từng docker run cho từng container rất dài dòng, khó nhớ và dễ gõ nhầm tham số.

VẤN ĐỀ 2

Thứ Tự Khởi Chạy

Khó kiểm soát thứ tự phụ thuộc (ví dụ: Database phải khởi động và sẵn sàng trước Backend).

VẤN ĐỀ 3

Kết Nối Mạng Phức Tạp

Phức tạp trong việc thiết lập IP và quản lý mạng liên lạc nội bộ giữa các container.

Phần 4

Docker Compose Là Gì? (Tổng Quan)

Docker Compose là công cụ định nghĩa nhiều container liên quan nhau trong một file YAML duy nhất (docker-compose.yml), rồi khởi chạy tất cả chỉ bằng 1 lệnh duy nhất.
MỤC 4.1

Cấu Trúc File YAML

Khai báo cấu hình tập trung cho toàn bộ cụm dịch vụ.

MỤC 4.2

Bộ Lệnh Điều Khiển

Bật, tắt, theo dõi log cụm dịch vụ chỉ với 1 lệnh đơn giản.

MỤC 4.3

Docker Network Nội Bộ

Các container tự động giao tiếp qua tên Service Name.

Phần 4.1

Cấu Trúc File docker-compose.yml Mẫu

version

Phiên bản cú pháp Compose.

services

Danh sách dịch vụ cần chạy (app, db, redis).

ports

Ánh xạ cổng giữa Host và Container.

environment

Khai báo các biến môi trường.

volumes

Gắn kết lưu trữ dữ liệu bền vững.

networks

Cấu hình mạng nội bộ cụm dịch vụ.

Phần 4.2

Bộ Lệnh Điều Khiển Docker Compose Cơ Bản

docker compose up -d
Khởi chạy toàn bộ cụm dịch vụ ngầm trong nền
docker compose ps
Xem trạng thái của các dịch vụ trong cụm
docker compose logs -f
Xem log thời gian thực của toàn bộ cụm
docker compose down
Tắt và hạ toàn bộ cụm dịch vụ
docker compose down -v
Tắt cụm và XÓA LUÔN Volume (Reset sạch dữ liệu)
Phần 4.3

Cơ Chế Docker Network Nội Bộ

MẠNG NỘI BỘ

Tự Động Kết Nối

Các container trong cùng docker-compose.yml tự động tham gia vào chung một mạng nội bộ cách ly an toàn.

SERVICE NAME DNS

Gọi Qua Tên Service

Backend gọi sang Database qua hostname db thay vì IP động. DNS nội bộ tự động phân giải địa chỉ chính xác.
